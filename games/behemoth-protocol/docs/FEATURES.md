### Practice URL parameters
`M0`–`M2` · various · `playtest: n/a`
Parsed in `src/config.ts`. A practice run (any of `seed`, `immobilize`, `addons`, `trailer`, `weapons`, `shells`, `cookoff`, `grades`, `mods`, `depot`, `biome`, `approach`, `map`, `mode`, `train`, `directive`, `objective`, `summary`, `condition`, `event`, `doctrine`, `mix`) skips the title screen and never saves.

| Param | Effect |
|---|---|
| `?seed=N` | Practice run on seed N, straight into its opening battle (which uses the run seed); winning goes to the map |
| `?immobilize=N` | Treads destroyed N s into the battle (fires once, so a drone revive sticks) |
| `?exit=N` | Extraction line N meters out; keeps the title and the save (for a quick trip to the depot) |
| `?addons=all` or `?addons=a,b` | Start with add-ons (sponsons get an autocannon and a rotary gun; `dorsalRing` a heavy cannon; `coax` a flak cannon) |
| `?trailer=missilePod,ammoBunker` | Start with a trailer; `-` = empty bay |
| `?weapons=turret:heavyLaser,prow:plasmaThrower` | Weapon per slot id (`slot:weapon` pairs) |
| `?shells=turret:ap,dorsalRing:canister` | Main-gun shell per slot id (`he`, `ap`, `canister`) |
| `?cookoff=N` | Magazine destroyed N s into the battle (it cooks off) |
| `?grades=reactor:3,sensors:2` | Core component grades (`component:gen`, gen 2 or 3) |
| `?mods=turret.traverse:3,armor.front.plate:2` | Mod levels (`part.track:level`; the track follows the last dot; `armor.front` is both front halves, `treads.load` the Load mod) |
| `?depot=N` | Opens the depot after N battles won, with 1000 salvage (Gen 3 grades show from N = 2) |
| `?biome=arctic` | Every battle in that biome, whatever the sector (`temperate`, `arctic`, `industrial`, `desert`, `wasteland`) |
| `?approach=pass` | Every battle on that approach (`plain`, `forest`, `urban`, `river`, `pass`; `none` = the biome's own mix) |
| `?look=autumn` | Every battle's look (§3 "Ground looks"; `spring`, `summer`, `autumn`, `deepSnow`, `windswept`, `thaw`, `cinders`, `rust`, `chemical`, `paleSand`, `redSand`, `hamada`, `ash`, `rustDust`, `toxic`); one its biome lacks is ignored. Cosmetic: doesn't make a practice run |
| `?mode=breach` | Every battle in that mode (`assault`, `breach`, `chase`); the node's strength still sets the target count. With `?exit=60` the fortress is close (Breach) |
| `?mode=intercept&train=engine,boxcar,boxcar,engine` | An Intercept's train, front to back (`TRAIN_CARS` ids; unknown names are skipped). Without `train`, the node's strength sets it |
| `?map` or `?map=N` | Opens the sector map at the start of sector N (default 1) instead of a battle; with `?biome`, that sector is drawn in that biome (for looking at the map art) |
| `?condition=night` | Every battle in that condition (`night`, `storm`; `none` = clear) |
| `?doctrine=longGuns` | Every battle's defenders fight that doctrine (`combined`, `armoredFist`, `entrenched`, `raiders`, `longGuns`; `longGuns` for field batteries) |
| `?mix=siegeTank:1,lightTank:2` | Every battle's enemy mix (`unit:weight` pairs, replacing the doctrine's; objective-only units are dropped; biome units aren't filtered by biome). For trying a new unit: `?seed=3&mix=siegeTank:1` |
| `?event=convoy` | Opens that event (`convoy`, `orders`, `hulk`, `dump`, `drop`, `scavengers`; `?event` alone, one drawn from the seed) on the first layer of sector 1, with a worn Behemoth (treads 60%, armor 50%, sensors 80%, munitions half) and 120 salvage |
| `?res=480\|576\|640` | Internal resolution (default 576×324) |
| `?terrain` | Dev tool: the terrain preview instead of the game (§1 "Terrain preview"; takes `seed`, `biome`, `approach`, `look`, `col`, `zoom=2`) |

### Dev console
`M3` · 96a22ba · `playtest: pending` · SPEC n/a (dev tool)
An HTML panel down the right of the page for playtesting and tuning. It's on in the dev server, and in any build with `?dev` in the URL (`?dev` doesn't make a practice run). Open it with `\` or the DEV tab at top right; close it with Esc, `\`, or ×. While it's open the game shifts left to make room. The status lines show the active scenes, fps, sim time and speed, seed/biome/approach/mode/condition, distance, speed, enemies, threat, the alert clock, kills, and salvage.
- **Time:** pause, step one sim tick (1/60 s), speed ×0.1–×4, the debug readout, restart the battle.
- **Behemoth:** god mode (sticky across battles), repair all (also puts out a burning reactor and ends Immobilized and the last stand), rearm (ammo and capacitor), immobilize, reactor critical, extract now, damage one component by N, a shot of N on an armor arc (goes through armor to the internals like enemy fire), add salvage.
- **Enemies:** spawn N of any unit (objective units included) `near` (on screen, ahead), `auto` (the way the alert clock sends it), or from `ahead`/`behind`/`left`/`right`. Also kill all (counts as kills, pays salvage), alert wave now, freeze enemies (they hold still and hold fire), no spawns (`encounter.off`), and live threat and alert pace.
- **Weather (live):** clear, night, or storm, swapped mid-battle (veil and weather included; a new storm squalls 2 s later).
- **New battle (reloads):** a form over every practice URL param (prefilled from the URL), a unit picker that appends to `mix`, a random seed, Launch, and Title (clear all). Keeps `?dev`.
- **Tweaks:** every number and boolean in every object in `tuning.ts` and the content tables (CHASSIS, WEAPONS, ENEMIES, ADDONS, TRAILER_MODULES, MATERIALS, OBSTACLE_CLASSES, CONDITIONS, MODES, DOCTRINES, BIOMES, APPROACHES, DIRECTIVES, MAP_EVENTS, GRADES, TRACKS, depot stock), with a path filter and a changed-only view. Edits apply live (the sim reads the tables in place). They're saved in `localStorage` (`behemoth-protocol/dev-tweaks`) and put back before the game starts on every load with the console on. Changed values show amber, the DEV tab counts them, and you can reset one table or all. A "this battle: chassis" table edits the live Behemoth's fitted chassis for this battle only.
- Files: `src/dev/console.ts` (DOM panel, `DevConsole`, `devEnabled`), `src/dev/tweaks.ts` (`TweakStore`, `leaves`), `src/sim/dev.ts` (`devSpawn`, `devRepair`, `devRearm`, `setInvulnerable`, `devKillAll`, `devWave`, `devExtract`, `devCondition`), `BattleDev`/`devHooks()` in `scenes/TopDownBattleScene.ts`, and wiring in `main.ts`. Sim hooks: `BehemothState.invulnerable` (checked in `damageArmor`, `wearPlow`, `damageComponent`, `hitTrailer`; never saved), `World.dev.frozen` (skips `stepEnemies`), `createCondition`'s `firstSquall`, `arrival` exported from `sim/encounter.ts`, `WeatherView.destroy`. Tests: `tests/sim/dev.test.ts`, `tests/dev/tweaks.test.ts`.
- **Gotcha:** the panel stops key events from bubbling, so typing in it never steers or fires (Phaser listens on `window`). A new global key binding in the game won't fire while focus is in the panel.
- **Gotcha:** saved tweaks are applied in `main.ts` before the Phaser game is created, but after every module has loaded. A constant derived from a table at module load (e.g. `const X = TABLE.a * 2` at top level) always keeps the shipped value; edit the source for those. Primitive exports (`RIPPLE_GAP`) can't be edited at all.
- **Gotcha:** console damage buttons (Immobilize, Hit, Fire) lift god mode for that one call, so they always land.
- **Gotcha:** switching the condition live doesn't update the HUD's condition label (set when the battle starts).

### Offline audio rendering
`M2` · fee5f6d · `playtest: n/a`
- `npm run render:music [-- [--demos | --voices | --sounds] <out dir>]` (`scripts/render-music.mjs`; `--demos` skips the battle renders, `--voices` renders only the instruments on their own, `--sounds` only the sound effects on their own; everything takes about 3 min) starts a Vite dev server, opens Playwright's headless shell over the DevTools protocol (Node's built-in `WebSocket`), imports `src/audio/music/render.ts`, and writes `renderAll()`'s WAVs, MIDI, and `.txt` reports to `renders/music/` (git-ignored): `sounds` (every sound effect in turn through the game's `Synth`: the one-shots at the sizes and distances the game plays them (`TAKES`), the held sounds, the drive in six states, a meltdown; start times in `sounds.txt`), `voices` (every instrument in turn, alone in the hall: two bars and a bar's ring each, start times in `voices.txt`), then for each piece its demo (`<piece>-demo`) and a scripted battle through the real sound effects with the music under it (`<piece>-battle`; see §13 "Music"). Renders schedule a bar at a time, just ahead, as the live player does (`byBar`: the render pauses before each downbeat), so the graph only holds a bar or two of notes and render time is a fair measure of what the music costs live (**Gotcha:** scheduling a whole piece up front took 4× as long: every pending note's nodes are processed from the start). The page keeps the renders and the script fetches them one at a time (**Gotcha:** all ten in one `Runtime.evaluate` result is too big a message: the call never returns). Add renders by adding to `renderAll()`. `CHROME_HEADLESS` overrides the browser.
- **Driving `Synth` offline** (`renderBattle` in render.ts): it plays everything at `ctx.currentTime`, so pause the render with `ctx.suspend(t)` at each step (a multiple of 128 frames), fire that step's sounds and `update()` the loops, then `resume()`. Override `running` to true (a suspended context reads as not running) and reset its private `voices` count each step: it frees voices on wall-clock timers, far behind a faster-than-real-time render, and its 48-voice cap would silently drop sounds.
- **Stems in one pass:** a 4-channel `OfflineAudioContext` (destination `channelCount` 4, `discrete`) with a `ChannelMerger`, each source split into its own pair. Two separate renders can't be compared sample by sample: every sound effect varies its pitch and level at random.
- Checking a render without ears: `ffmpeg -ss <s> -t <s> -i x.wav -af astats -f null -` (read the *Overall* block: peak and RMS level), a `lowpass=f=90` chain before `astats` for the energy in the engine's register, and `-lavfi showspectrumpic=s=1600x700:legend=1:fscale=log:stop=8000` for a spectrogram to look at.
- **Gotcha:** in zsh, `set -- $var` doesn't split words; wrap per-section loops in `bash -c`.

## 2. Movement and camera

### Behemoth movement
`M0` · `initial` · `playtest: pending` · SPEC §4.2
Cruise/min/top speeds, accel and brake, lateral steering capped by forward speed, heading follows velocity. Speeds scale with tread integrity: `floor + (1 − floor) × integrity^0.75` per working set (`DEGRADE.treadSpeedFloor` 0.5, `treadSpeedExponent` in tuning.ts; `treadSpeedScale` in behemoth.ts), so worn treads hold half speed and only a destroyed set gives zero (f4b61e9, user's call: it used to fall toward zero). The hull heading is clamped to atan(`lateral.maxRatio`) in `stepMovement`, up to ~41° (raised from ~31° so rock fields near river crossings stay passable).

### Eased steering
`M2` · `initial` · `playtest: pending` · SPEC §15 "Steering and front armor" (step 1 of 3)
Sideways acceleration is jerk-limited, and the Behemoth eases to a stop at the field edge.
- `easeToward(v, a, target, maxAccel, jerk, dt)` in `sim/math.ts`: an S-curve with a one-step look-ahead (without it, the fixed step arrives with ~12 units/s² left and snaps).
- `BehemothState.ay`; `stepMovement` steers through it. `edgeApproachSpeed` (behemoth.ts) caps the target near the field edge (`MOVEMENT.edgeMargin` = 0.6 of the room: the target shrinks as the hull closes in).
- Class II `lateral: { accel 45, jerk 142 }` (was accel 36, no jerk; jerk 150 until Nov 22, 2026, when the user asked for a little smoother turn-in and return, −5%, `7dfa568`): 10–90% turn-in ~0.58 s, full in ~0.77 s, release settles in ~1 s. Tune `accel`/`jerk` in content/chassis.ts.
- Deflection still writes `vy` directly (a shove).

### Mass and tread capacity
`M2` · `initial` · `playtest: pending` · SPEC §5.3
Weapon and add-on mass against tread capacity scales speed, acceleration, and agility. The depot shows load with install previews, and the HUD shows an OVERLOAD label.
- `WeaponDef.mass` (tons), `ChassisDef.massCapacity` (Class II 280; the starting loadout is 245), `MASS` in tuning.ts.
- `sim/behemoth.ts`: `massScale(mass, capacity)` (+15% empty, 1.0 at capacity, −2% per 1% over, floor 0.4), `loadMass` (wrecked weapons count), `massCapacity` (= working tread sets), `mobilityScale` = tread × mass, used by `speedLimits`, accel, and `lateralLimit` (also the deflect clamp in collision.ts).
- Chassis speeds mean "at rated capacity", so **tests compare against `speedLimits(b)`, not `chassis.speed`**. `createBehemoth` and `restoreBehemoth` start at the Behemoth's own cruise.
- Depot: `loadOf(snapshot, swap?)`; the "For sale" row shows `Load m/cap t  Cruise n` (amber when over), install/remove labels carry the mass change, and hovering previews `before>after`. HUD: the speed bar scales to the unloaded top speed.

### Camera-follow frame
`M0` · `initial` · `playtest: pending` · SPEC §4.2
Anchored ¼ from the bottom at cruise, with smoothing lag (a surge pulls ahead, braking drifts back). It never scrolls backward and has a hard cap at 55%. `CAMERA` in tuning.ts. `frameFocus(b)` (world.ts) follows a point behind the hull while towing a trailer. The one backward scroll is `centerFrame` in the last stand.

### Vertical scrolling
`M0` · `initial` · `playtest: pending` · SPEC §4.1
Battles scroll up the screen with HUD side panels. W/S = speed, A/D = steer. The sim stays camera-agnostic (+x = forward); only `src/render/` maps it to screen-up.

## 3. Terrain

### Terrain chunks
`M0` · `initial` · `playtest: pending` · SPEC §4.5
Generated ahead per (seed, chunk), independent of order. Forest, building, road, each with damaged/destroyed/flattened states. `speedAt(x, y, mobility)` gives per-mobility speed; `isCover` covers forest (intact/damaged) and buildings.

### Rock outcrops and ridges
`M1` · `initial` · `playtest: approved` · SPEC §4.2, §4.5
Rock capsules (outcrops and ridges) in `sim/terrain.ts`, drawn after forests/towns so existing seeds keep their layouts apart from the rock. `laneCenter` keeps a 5-tile lane rock-free. `generateChunk` paints one chunk ahead and `fillDeadEnds` fills dead ends right to left (merged 3-column lookahead). Rock covers ~3.5% of tiles, mostly blocky masses against the field edges.
- Bot, 40 seeds × 3 min driving blind: 193 contacts, held ~0.55 s on average, 2.7 s at worst, no crumbles (the regression test covers 6 seeds).

### Rivers (terrain type 6)
`M1` · `initial` · `playtest: pending` · SPEC §4.5
Shallows plus a deep channel with fords. The Behemoth fords at minimum speed with tread wear by distance; tracked enemies cross only at fords.
- Materials `shallows` and `water` (content/terrain.ts), with a `wading` field (Behemoth speed cap + tread wear per 100 units). `WADING` and `river*`/`ford*` in `TERRAIN_GEN` (tuning.ts).
- Generator: `chunkRiver(seed, ci, rows, recipe)` (internally `riverOf`, cached in `neighborOf`) on its own RNG stream, `riverCenter`, `riverPaint` (water/shallows/'approach'/'margin', mapped to the river's own `shallows`/`channel` materials, so arctic rivers are ice over thin ice). Rivers paint over forest/towns. Rock and dead-end filling stay off rivers plus a 2-tile margin (`nearRiver`). Ford approaches turn buildings to road.
- `Terrain.riversNear`, `Terrain.groundAt(rect)` (was `wadingAt`; now also returns `grip` and the HUD `label`). `b.wading` is refreshed at the end of `resolveBehemothCollisions` (`ford()` applies wear by distance); `wadingCap` limits the target speed in `stepMovement`, with `WADING.drag` decel.
- AI: deep water is impassable to tracks and walkers, so `ai/nav.ts` routes find the fords and bridges (§7 "Behaviors as data and shared navigation"; `viaFord` is gone).
- Render: `water0/1`, `shallows0/1` tiles with per-tile ripple, `Effects.splash/wake`, no scorch or track marks on water; the HUD speed shows `WADE`/`FORD`.
- Bot, 20 seeds × 3 min: a river every ~50 s, ~4 tread HP and ~8 s per crossing (worst 13 HP). Seed 4 has a river ~17 s in.
- **Gotcha (M3):** spacing is now `hasRiver` (a chunk has a river if it rolled one and the chunk before doesn't *have* one), worked forward from `riverFirstChunk`. The old rule (didn't *roll* one) suppressed itself at high chances; the change moved some rivers on old seeds.

### Biome × approach recipes
`M3` · `initial` · `playtest: pending` · SPEC §3.1, §4.6, §15 "Biomes and terrain (M3)"
A battle's terrain is a `TerrainRecipe` `{ biome, approach }` (approach null = the biome's own mix). Five biomes (temperate, arctic, industrial, desert, blasted wasteland) and five approaches (open plain, forest line, urban district, river crossing, mountain pass).
- Content: `content/biomes.ts` (`BIOMES`, `FeatureMix` per-chunk counts/chances, river materials), `content/approaches.ts` (`APPROACHES`: `scale` multipliers on the mix, `townSize`, `forestSize`, `cliffs`, `laneAmplitude`, `avenue`). Shape knobs in `TERRAIN_GEN` (tuning.ts): `craterField`, `minefield`, `fortLine`, `trapLine`, `hedgerow`, `farm`, `lake`, `snowdrift`, `factory`, `tankFarm`, `rail*`, `cliffKnotCols`, `bridgeWidth`, `lightBridgeShare`, `firstDefenseChunk`, `riverMaxChance` (replaced `riverChance`; `forestBlobsPerChunk`/`townChance`/`rockPerChunk` moved into the biome mix).
- Generator (`sim/terrain.ts`): `chunkFeatures` keeps forests → towns → rock on the original stream and order (temperate keeps its old forest/town/rock layouts); every new kind draws on its own stream (`SALT`). `paintColumn` paints `PASSES` in order, each feature deciding what it claims (`featurePaint(..., cur)`), then rails, rivers, cliffs, rock. `besideLane` places factory compounds and tank farms clear of the lane. Urban `avenue` turns buildings within 1.5 rows of the lane center to road. `generateChunk(seed, ci, rows, recipe)`; `new Terrain(seed, rows, recipe)`; `createWorld({ recipe })`.
- Run (`sim/run.ts`): `battleRecipe(run, override)` (the sector's biome and the node's approach; see "Sector map") and `recipeName`. Scene passes `recipeFromUrl()` (config.ts). HUD stats name it, and the map's intel panel shows the approach; the debug line shows it.
- Tests: `tests/sim/biomes.test.ts` (determinism, order independence, start clear, lane free of rock/compounds, tracked units can drive every recipe end to end, biome-only materials, approach shares, cliffs, run recipes).
- **Gotcha:** `neighborOf` caches chunk features and rivers in a module-level `chunkCache` (96 entries, keyed by seed/rows/recipe/chunk); it's a pure function of those, so it never needs clearing. Painting checks only features whose `colSpan` reaches the column (`reaching`); a new feature kind needs a `colSpan` case or it never paints.
- **Gotcha:** rock paints over everything except `ROCK_SPARES` (building, road, factory, fuel tank). Rails and defenses must not punch holes in outcrops: holes left notches that boxed the hull in (seed 2 crumbled until this rule).
- **Gotcha:** a hidden mine is drawn as open ground (the see-through `clear` frame over the painted ground, §3 "Ground looks"), so minefields only claim `ground`.
- Bot (terrain only, 6 seeds, follows the lane, never fires): before biomes −46 treads / −40 front armor / 191 s / 6 of 6; now per recipe −47 to −70 treads, −10 to −76 front armor, 186–238 s, 3–6 of 6 within 5 min. Mines and traps are the new costs. Desert −35 to −54 treads; wasteland −62 to −76 (the harshest).

### Common terrain features
`M3` · `initial` · `playtest: pending` · SPEC §4.5, §4.6
Craters, tank traps, walls and bunkers (fortified lines), minefields, and bridges, in every biome. Materials in `content/terrain.ts`, with new `MaterialDef` fields: `bearing`, `breaksTo` (a material or `under`), `explodes`, `hidden`, `scars`, `debris`.
- **Craters:** `crater` material; `Terrain.damage` on open ground (`scars: 100`) turns it into one; mines and fuel tanks break to one.
- **Tank traps:** `tankTrap`, obstacle class `trap` (new in `OBSTACLE_CLASSES`, with `soft` for crops and rails). Checkerboard belts (`traps` feature) and in front of fortified lines.
- **Walls and bunkers:** `wall` (heavy, blocks everyone), `bunker` (heavy, garrisoned: protection 0.8). `fort` feature: a wall at a column with `gates`, bunkers `bunkerBehind` columns beyond it, a trap belt `trapsAhead` columns before it with its own gates; never near a river.
- **Minefields:** `mine` (1 HP, `hidden`, `explodes` 14/30, `breaksTo: 'crater'`, obstacle trivial so the treads set it off). `Terrain.reveal` marks swept tiles `seen` (called from `stepConcealment` with the sensor reveal radius × `CONCEALMENT.mineSweep` 1.15, user's call Nov 22, 2026, `7dfa568`: mines show a bit sooner on Gen 1 sensors; only re-sweeps when the hull moves to a new tile).
- **Bridges:** `bridge` (400 t, 120 HP) and `lightBridge` (300 t, 50 HP), `bearing.give: 'span'`; `Tile.under` holds the water. `River.bridge` (rows, kind) is drawn on its own stream clear of fords. `Terrain.crossings(rv)` = fords + the bridge while it stands; Routes (`ai/nav.ts`) cross at either, and straight over a frozen river (thin ice is passable). A destroyed bridge tile (`damage`) or an overload (`bear`) brings down the whole span (`collapse`, flood fill) and emits `bridgeCollapse`.
- **Gotcha:** `tileChanged` now carries `mat`, the material that changed. Read it instead of the tile: a fallen bridge or a mine has already turned into water or a crater by the time the renderer sees the event.

### Biome terrain
`M3` · `initial` · `playtest: pending` · SPEC §4.6
- **Temperate:** `farmland` (soft: flattened by the treads), `hedgerow` (trivial; slows vehicles, conceals infantry). `farm` feature (hedged 60%) and lone `hedge` lines.
- **Arctic:** `ice` (`grip` 0.3), `thinIce` (`grip` 0.4, `bearing` 200 t `crack`, `breaksTo: 'water'`, 12 HP), `snowdrift` (`wading` cruise cap, label DRIFT). Rivers use `ice`/`thinIce`; `lake` feature (ice rim, thin-ice core) and `drift` feature. Movement: `stepMovement` scales forward accel, braking, lateral accel and jerk by `b.wading.grip` (floor `MOVEMENT.minGrip`), and the edge approach uses the scaled values. `BEARING.crackRate` 60 HP/s per 100% overload.
- **Industrial:** `factory` (260 HP, medium obstacle, 5 salvage, garrisonable), `fuelTank` (25 HP, `explodes` 40/50 with a 0.25 s fuse, `breaksTo: 'crater'`), `rail` (soft; torn when crushed). `factory` feature (road ring, 40% walled compounds with gates), `tanks` feature (grid 2 apart, so blasts chain), rails per `railStretch` chunks.
- **Desert**: `dune` (`wading` cruise cap, label SAND), `wadi` (river material for both banks and channel: passable, conceals and covers infantry), `derrick` (40 HP, shots pass through, `explodes` 44/60 with a 0.4 s fuse, 3 salvage, `breaksTo: 'crater'`). Features `dune` (oval, long across the field; `TERRAIN_GEN.dune`) and `oilfield` (square block placed with `besideLane`, derricks on a 3-tile grid that don't chain; `TERRAIN_GEN.oilfield`).
- **Blasted wasteland**: `wreck` (150 HP, medium, blocks fire, garrisonable cover 0.5, 4 salvage), `glass` (`grip` 0.5, `slipTag` GLASS). Features `wrecks` (patch; `TERRAIN_GEN.wreckField`) and `blast` (oval: glass inside `blastSite.core`, craters around; claims anything). `BiomeDef.ruins` sets `RUINABLE` tiles (building, factory, wall, bunker) damaged or destroyed when `generateChunk` creates them (cell noise salt `0x7a1d`). Rubble placed this way pays no salvage; a damaged ruin still pays when it's knocked down.
- **Gotcha:** the HUD speed tag comes from `b.wading.label` (FORD, WADE, DRIFT, SAND, or the `slipTag` of the slippery ground under it: ICE, GLASS), set by `groundAt`. `isWet(mat)` (content/terrain.ts) is the check for river water (splashes, pools fizzling); snowdrifts have `wading` but aren't wet.
- **Limits:** dunes don't block sight (long sightlines are the point). Arctic gets an occasional fuel-tank farm (`tankFarms` 0.05) as a fuel depot; drop it if it reads oddly. Hedgerows are `trivial` like forest (0.05 tread per tile at cruise; bot ~1 HP a battle). Wasteland wrecks are single tiles, and ruins pay no salvage for the part already knocked down.

### Ground looks (seasons)
`M3` · `c8f06a7` · `playtest: pending` · SPEC §4.6 "Looks", §15 "Terrain looks (M3)"
User request (Nov 23, 2026): maps looked too much alike. Cosmetic only. Each battle draws a **look** from its terrain seed (three per biome: a season in temperate, its counterpart elsewhere). The look recolors the tiles, and the open ground is painted per pixel under them: big dithered patches of three tones, bare patches, ragged fringes where the ground meets other terrain (river banks, leaf litter, aprons, scree, …), clustered decals, and now and then old tank ruts.
- `render/looks.ts`: `Look` (`tones` ×3 `Ramp` [base, light, dark], `bare` + `bareCover`, `bank`, `accents`, `decalDensity` + `decals` weights, `ruts` chance, `pal` overrides), `LOOKS` per biome, `lookFor(biome, terrainSeed, wanted?)` (salt `0x5ea5`), `lookPalette(biome, look)` (the look's first tone becomes `grass*`). `Pal`, `BIOME_PAL`, and `biomePalette` moved here from tileArt.ts so the painter and tests stay free of Phaser.
- `render/ground.ts` (pure): `GroundPainter(src, look, pal, ci, cols, tile)` paints a chunk one tile column at a time (`paintColumn(lc)`) into `pixels` (RGBA, screen orientation); `paintGround` does a whole chunk. Noise: `Grid` (value noise, lattice hashed once per chunk) and `Fbm`; tone octaves 320/96/32 px with thresholds `TONE_LOW`/`TONE_HIGH` (0.42/0.6 ≈ 28/45/27%); bare octaves 56/20 px with `bareThreshold` (measured quantiles). `FRINGE_OF` (material → fringe) and `FRINGE_WIDTH` (px); only tiles in `SHOWS_GROUND` (ground, mine, crater, tank trap) take fringes, decals (`STAMPS`, letter-coded colors), and ruts (`rutsNear`: one chance per 3 chunks, a sine path, gauge 8 px).
- `render/terrainView.ts`: picks the look (`TerrainView.look`), gets per-look sheets from `lookSheets(scene, biome, look)` (tileArt.ts; keys `tiles_<biome>_<look>`, `clumps_<biome>_<look>`, drawn on first use; `makeTiles` is gone), and keeps one `ground_<ci>` canvas texture per chunk at depth −0.5. The chunk coming up next is painted `PAINT_BUDGET` (4) columns a frame, ones in view at once; textures are dropped behind the view and on scene shutdown. Open-ground tiles use the see-through `clear` frame and are hidden; tank traps, swept mines, craters, flattened woods, and wrecks are drawn without a grass backing.
- Practice: `?look=autumn` (any look id; ignored if the battle's biome lacks it; not a practice-run trigger); the dev console's New battle form has it, and its status line and the debug overlay show the look.
- Cost: ~5 ms a chunk (16 columns × 21 rows) in Node, spread over 4 frames.
- Tests: `tests/render/ground.test.ts` (deterministic and opaque, a mine paints exactly like ground, banks line water, all three tones get sizable shares, bare cover near the look's, seams match across chunks, looks picked from the seed).
- **Gotcha:** the ground layer is painted once from the tiles as they were then: fringes don't follow later changes (a burnt wood keeps its litter; a fallen bridge's banks were already there). Craters made in play are see-through, so they sit on the painted ground.
- **Gotcha:** a mine must paint exactly like ground (the test checks it): don't make anything in ground.ts depend on `mine` vs `ground`, or minefields show before they're swept.
- **Gotcha:** the top tile column of a chunk takes fringes from the next chunk, so painting waits for the world to make it (`Terrain.tile((ci + 1) * CHUNK, 0)`); the world makes chunks one ahead, so that chunk is still above the frame.
- **Limits:** no scorch around craters made in play; enemies are rust red, so check them on the reddish looks (autumn, red sand, rust, rust dust); the attract mode always uses the seed's look.

### Settlements, roads, cars, and footbridges
`M3` · `03303f9` · `playtest: pending` · SPEC §4.5, §4.6 "Settlements and roads", §15 "Settlements and roads (M3)", §16 Q36
User request (Nov 23, 2026): more buildings and variants in every biome, roads, cities with skyscrapers and government buildings, farmhouses and barns, tree species, small bridges the Behemoth can't use, parked cars that act as rubble. Tiles carry cosmetic **art** set at generation; the material still decides play.
- **Content** (`content/structures.ts`): `STRUCTURES` (21 kinds: footprint `cols` along travel × `rows` across, `styles`, a 1×1 `fallback`), `SETTLEMENTS` (per biome and `Setting` village/town/city: `lots` weights, shares of built-up area, and `landmarks` chances), `TREES` (species weights per biome), `ROADS` (country road surface, width, car share per biome), `RoadStyle`, `TileArt` (structure piece with `uid`/`dc`/`dr`, hall nine-slice, tree species, road surface). Tuning: `TERRAIN_GEN.settlement` (block sizes, `townArea`, car shares), `farm.yard`/`silos`, `road` (`stretch`, `knotChunks`, `swing`, `crossMin`; `townFill` is gone). Mix keys `roads`, `crossRoads`, `footbridges` on every biome; approach fields `townWidth`, `factorySize`, `city` (urban: towns ×2 along, ×2.8 across; factories keep ×1.4).
- **Materials** (`content/terrain.ts`): `footbridge` (14 HP, tracked 0, foot 1, `bearing` 20 t `span` with `quiet`, `breaksTo: 'under'`; hovercraft skim under it), `car` (16 HP, light obstacle while standing or burnt out, tracked ×0.6, cover 20%, burns, no salvage). `bear()` doesn't count a `quiet` span toward the hull's jolt; `bridgeCollapse` now carries `mat` (the scene and the cues scale the splash and skip the shake for a footbridge).
- **Generator** (`sim/terrain.ts`): `Tile.art`, `Tile.links` (`LINK` bits fwd/right/back/left, same as screen up/right/down/left). `layoutTown` (own stream `ART_SALT.town`): `streetLines`/`blockRuns` cut the town into blocks, the avenue band (urban) becomes `avenue` road, landmarks go first in the biggest block they fit (centered), then each free cell takes a weighted lot (`weight × area` for structures that fit). `layoutYard` puts a barn, farmhouse, maybe a silo in a 3×3 corner of a crop field, on open ground. Country roads: `Road` features (one per chunk on a road stretch, between knots `ROAD_KNOT` apart, eased; `onRoad` covers the rows to the next column's so it never breaks), cross roads on SALT `crossRoad`; painted in the `road` pass (after hedges, before towns) over `ROAD_CLAIMS`. `featureArt` gives each painted cell its art; `paintColumn` drops the art when anything paints over the cell, and passes `ground` to rock over a country road. River `footbridges` (rows; own stream; one where a country road meets the river). `generateChunk` paints `MAX_FOOTPRINT` columns behind the chunk, checks each structure's footprint (`footprintWhole`: every tile there with the same `uid` and place, still a building) or swaps in `fallbackArt`, drops art that no longer fits its material (`artFits`: dead-end filling may have made it rock), and sets `links` on roads, cars, and walls (`linksOf`; country roads and walls run on off the field's sides).
- **Render:** `render/tileFrames.ts` (Phaser-free): `tileFrame`, `tileOverlay`, `frameName` builders, `sheetFrameNames(biome)`. `render/structureArt.ts`: `drawStructure` (each drawn whole, lit from the upper left, shadow inside its own footprint), `drawHall` (48 px nine-slice), `drawRoad` (country bands that turn toward their links and fill out at junctions; town surfaces with curbs on unlinked sides), `drawWall`, `drawFootbridge`, `drawTree`, `drawCar`, `damageTile`. `render/tileArt.ts` shelf-packs every frame onto one 512-wide sheet per biome and look (`packSheet`; structures only for `structuresOf(biome)`). Cars are overlays (no jitter) over their road frame; sparse species (palm, scrub, dead) stand on the painted ground. New palette keys in `PAL` (panes, sheet metal, marble, domes, lawns, paint, asphalt, cars, pine, birch, scrub) with biome overrides.
- **Dev tool:** `?terrain` (§1 "Terrain preview").
- Cost: chunk generation ~0.3 → ~0.4 ms. Bench (12 battles, stock): same outcomes, mean treads 68% (62% before; different terrain).
- Tests: `tests/sim/settlements.test.ts` (footprints whole across chunk edges, biome structures, cities, farmyards, species, links both ways, rock over roads, footbridges, cars, generation order with art), `tests/render/tileFrames.test.ts` (every tile in every state of every recipe asks for a frame its sheet has). Updated: rivers count footbridges as a crossing, infantry may cross on one, the drone test allows a car's tread wear.
- **Gotcha:** a structure's art is checked against the *raw* paint of the columns behind the chunk (dead ends aren't filled there), so in a rare case a footprint split by a filled dead end differs either side of a chunk edge. Cosmetic only.
- **Gotcha:** every lot is a `building` (never `factory`): the lane test bars factory tiles from the lane, and towns sit across it.
- **Gotcha:** links are worked out at generation; a bridge that falls leaves its road's links pointing at water (cosmetic).
- **Limits:** placeholder art; roads change rows in steps (a staircase on the diagonals); towns ignore the country road (they pave over it); no level crossings at rails; footbridges only over rivers (no small streams yet).

### Round craters, bridge edges, and painted dunes and drifts
`M3` · `dfa7791` (bridges), the rest `eb83787` · `playtest: pending` · SPEC §4.5 (Craters, Bridges), §4.6 (Arctic)
User requests (Nov 23, 2026): a big blast's crater was dozens of small ones; bridge sides were just where the deck texture stopped; dunes and drifts were horizontal bars. Cosmetic only: the sim is untouched.
- **Craters** come in three sizes (user's call, after a first pass that joined every patch into one shape: sometimes a mix of small and large, with 1×1, 2×2, and 3×3 round craters). `craterPiece(around, variant)` in render/tileFrames.ts packs cratered ground: a tile is part of a 3×3 crater if its block on a grid of threes (shifted by the seed) is all crater and the seed's roll passes (`CRATER_ODDS[3]` 0.7); else of a 2×2 on a grid of twos (0.85), then on the same grid shifted a tile each way; else it's a single shell hole. Frames are `frameName.crater(size, v, dc, dr)` (`cr.<size>.<v>.<dc>.<dr>`; 4 variants of the single, 2 each of the bigger). `crater` in render/tileArt.ts draws each size whole (a lip, a wall, a floor that deepens to the middle, a wobbly outline, lit from the upper left) and it's cut into tiles like a structure.
- **Bridges:** `frameName.bridge(light, edges, damaged)` (`b.<g|l>.<0–3>[.d]`), `edges` from `bridgeEdges` (1 left, 2 right: the tile on that side isn't the same bridge, a road, or a car, so the abutments' paving doesn't get a rail). `deck` in tileArt.ts draws the edge: a girder with stiffeners and rivets (girder bridge), a kerb and a handrail on posts (light bridge), and its shadow on the deck.
- `tileFrame(t, shimmer, around?)` takes where the tile is (`Around`: seed, col, row, and a tile lookup); `TerrainView` passes it only for craters and bridges. Without it a crater draws as a single hole and a bridge with no edges.
- **Dunes and snowdrifts** are painted into the ground, not drawn as tiles (`tileFrame` gives them `clear`): `DRIFTS` and `RIDGE` in render/ground.ts. On their tiles the painter draws ridges: crests 11 px apart running across the wind (down and to the right of the screen), bent by a slow noise so they wander and fork, each a lit windward slope, a bright crest, and a shaded lee, fading out over 7 px where the patch ends. A snowdrift also lays snow under its whole patch (with the ragged `snow` fringe round it as before); a dune ripples whatever ground tone it's on.
- Tests: `tests/render/tileFrames.test.ts` (the packing: every big crater whole, a mix of sizes, a block needs all its tiles; bridge edges; every generated tile's frame is on its sheet).
- **Gotcha:** which crater a tile belongs to is worked out in the renderer every frame from the live terrain, because craters appear in battle: a new crater tile can complete a block, and the tiles round it then redraw as one bigger crater.
- **Gotcha:** dunes and drifts are in the chunk's ground texture, painted once when the chunk comes up; nothing in battle changes them (neither material can be damaged).
- **Limits:** big craters sit on fixed grids, so they can line up; round craters leave corners of plain-looking ground that still play as crater; a bridge's ends have no abutment art of their own, and its edge throws no shadow on the water; a snowdrift's patch is still blocky at tile scale under its fringe.

### Rail line (an armored train's track, station, and bridges)
`M4` · `uncommitted` · `playtest: pending` · SPEC-armored-train.md §T3, §T9
An Intercept battle's terrain has one hardened track from its first column to its last, off to one side of the field, with a station at the start and a rail bridge over every river. It's a recipe option (`TerrainRecipe.line`), so every other battle's terrain is untouched.
- **Course** (`sim/terrain.ts`): `lineSide(seed)` picks the side; `lineBase` is the mean row plus a wander between knots (`TERRAIN_GEN.railLine`: `meanRow` 0.27, `wander` 1.5, `knotCols` 24, level through `levelCols`); `lineAt` holds it level `riverFlat` columns either side of each river (`lineCrossing`) and bends back at `riverSlope`; `lineRowOf` is its tile row. Remembered by column on the resolved recipe (`Resolved.line.memo`).
- **Painting** (`paintColumn`, after everything else and from column 0, so through the clear start too): `lineColumn` gives the track rows; the tile either side is the railbed (cleared to open ground unless it's in `RAILBED_KEEPS`); rock stays `rockClear` rows off (also in `fillDeadEnds`' lane test); the station is a `road` platform either side and `building` tiles `station.depth` rows deep on the narrow side.
- **Rivers:** `RailLineSpec.rivers` forces a river in those chunks (`hasRiver`); `riverShape` is the river before its bridges (the line plans from it); `lineBridge` sets a `railBridge` three rows wide on the line's row, drops fords within a row of it, and adds one on the wide side if none is left. `railLine(exitX)` in `sim/world.ts` picks the chunks (`TRAIN.rivers` of the way).
- **The lane** moves over: `laneAt` is `laneCenter` pushed `laneGap` rows clear of the line on its wide side. Every internal lane use and `Terrain.laneY` go through it.
- **Materials** (`content/terrain.ts`): `track` (open ground, `scars`: breaks to a crater at the cratering threshold) and `railBridge` (300 HP, `bearing.limit` Infinity, falls as a span); `isLine(mat)`. `Terrain.damage` ignores a line tile when `credit` is false (enemy fire) or it's shielded (`Terrain.shield`, set by the train; a bridge span is shielded whole). The treads don't tear it (no obstacle).
- **Terrain API:** `hasLine`, `lineSide`, `lineRow(col)`, `lineY(x)` (the track's row eased over `smooth` columns at a step: what a train follows), `lineCut(col)` (broken columns, kept after their chunk is pruned), `strew(col, row)` (a wreck lands: open dry ground becomes `wreck`).
- **Art:** `Tile.links` (`lineLinks`) says which way a track tile bends to the next row, or that a bridge tile carries the rails; frames `track`, `track_fr/fl/br/bl`, `rb.<edges>[.r][.d]` (`tileFrames.ts`, `hardRails` and the deck in `tileArt.ts`); `ballast` fringe.
- Preview: `?terrain&mode=intercept&seed=3` (any biome and approach).
- **Gotcha:** the track's rows are whole tiles and it steps diagonally; knots and river crossings sit on tile centers, or a course hovering on a row boundary jogs the track back and forth.
- **Gotcha:** a bridge's end columns follow the banks, which shift row to row, so an end column can have deck on the line's row and bank beside it.
- **Limits:** placeholder art (the bends are two straight slants); no level crossings where roads meet the track; the station is a platform and a plain building strip; lakes under the line become causeway (the track paints over ice).
- Tests: `tests/sim/railLine.test.ts` (unbroken, railbed, bridges, lane and fords, smooth path, station, hardened track rules).

### Terrain hazards
`M3` · `initial` · `playtest: pending` · SPEC §4.5, §4.6

## 4. Collisions

### Crush and plow
`M0` · `initial` · `playtest: pending` · SPEC §4.2

### Deflect off rock
`M1` · `initial` · `playtest: approved` · SPEC §4.2
Rock is immovable, blocks fire, and enemies can't pass it. The hull glances off with a slide, or is held at the face and shoved, with scraping and sparks. A crumble failsafe breaks rock when the hull is boxed in.
- The `immovable` class in `content/obstacles.ts`; `DEFLECT` in tuning.ts. `deflectOffRock` (sim/collision.ts) runs before crushing: each overlapping rock tile pushes the hull out along the shallower axis, and a tile at the nose within `FACE_DEPTH` (2 units) always counts as the face (otherwise sliding along a face flip-flops).
- The face contact (ram damage, armor half, spark) is `faceContact`; see Split front armor.
- State: `b.deflect {dir, flips, spark}`. The slide direction is picked once at contact (`slideDirection`); steering mid-slide is ignored on purpose (it caused in-place flip-flopping against rock alongside).
- **Gotcha** (fixed `c8f06a7`, Nov 23, 2026): the shove writes `vy` directly but leaves the eased sideways acceleration `b.ay` from before, so clearing the face now zeroes `ay`. Without that, a hull that slid off flush with the face's end was pulled back onto its corner every other tick: a fresh head-on hit (speed dip and all) each time, until it crawled to a stop (practice `?seed=4&biome=industrial`, x ≈ 774, a non-steering hull; regression test in `tests/sim/collision.test.ts`). Don't treat a sliver of sideways overlap at the nose as alongside to fix such things: that lets blind hulls box themselves in (seeds 2 and 18 grind rock).

### Behaviors as data and shared navigation
`M3` · `b97ec63` · `playtest: pending` · SPEC §7, §15 "Enemy AI (M3)", §16 Q17
The first two phases of the user's AI review (Nov 2026). **Behaviors are content:** every unit's `behavior` is a typed def with its own numbers, built by a preset, and the step functions read only the def. **Navigation is shared:** a behavior says where it wants to be (a `Goal`) and `navigate` gets it there, straight when the way is clear, otherwise along an A* route over the tiles costed by the ground's slowness plus hazards. Units also push apart. Phase 1 changed nothing in play (a fingerprint of 33 seeded battles matched to the last step and RNG draw); phase 2 is the change.
- `content/behaviors.ts`: `BehaviorDef` = `skirmisher | holdAhead | ambusher | fixed | convoy | charge | stalker`, each with `rearInset`, `siege: SiegeDef | null` (the last-stand ring, which took over `EnemyDef.siege`; null keeps the unit's own behavior, replacing the old convoy/charge special case) and an optional `weave` (took over `EnemyDef.evasive`; the `skier` behavior is now `skirmisher` + `weave`). Kind settings: `orbit`, `replan {every, flip}`, `lead`, `arc`, `laneGap`/`laneStep`, ambusher `reach`/`recheck`/`laneClear`/`laneReach`/`score`, convoy `lookAhead`/`idlePace`, charge `maxLead` (was `BOMB.maxLead`), stalker `hold`/`sideGap` (was `WALKER.sideGap`)/`stepAside`/`across`. `behaviorBand(def)`: the band a spawn rolls `orbitRange` from. `EnemyDef.engage` is gone.
- `sim/ai/index.ts` `behave(e, w, dt)`: the goal (the behavior's, or `besiege` in the last stand when `siege` isn't null) → `navigate` → `weave`. `moveEnemy` adds `separation` and keeps the old slide/swerve as a last resort against walls.
- `sim/ai/nav.ts`: `Goal {x, y, mode: 'pace' | 'arrive' | 'speed', speed?, contact?}`. Each step the goal moves out of a marked zone (`clearOfZones`) and off impassable ground (`onOpenGround`: nearest open tile within `snap`, favoring the unit's side and away from the hull). Every `NAV.replan` (0.4 s, staggered by id) `lineClear` checks the straight line: `pathBlocked` (rock, buildings, deep water for tracks, allowing for width), slow ground below `NAV.slow` (0.6) between the end tiles, a zone, explosive terrain, or a cut across the hull's path (unless the unit starts inside it). If it isn't clear, `plan` runs A* (8-way, no corner cutting) over a window `pad` columns past both ends (≤ `maxCols`), smoothed into straight legs (`legOk`: no costlier ground than the route's own). Following a route: 'pace' goals add the hull's velocity (or the hull runs them down), 'speed' keeps its speed, and the last leg is the goal itself as asked. An unreachable goal ends at the nearest reachable tile (kept pace with, for 'pace').
- Costs (`NAV` in tuning.ts): 1 / ground speed; `edgeCost` 0.75 beside impassable tiles for units of radius ≥ `wideAt` 7; the hull's footprint plus `hull.lead` 0.75 s of its travel, `hull.cost` 25 on its line falling to `hull.edge` 0.2 × that at the sides (a unit caught in front gets out sideways); a marked barrage zone `zone.cost` 30 once `zone.react` 0.8 s have passed (slow troops still get caught, so luring a volley onto them works); standing fuel tanks and derricks `blast.cost` 4 within `blast.share` 0.6 × their blast radius; the unit's current route × `stick` 0.6 (no flip-flopping).
- `separation`: inside radii + `sep.gap` 2, `sep.gain` 8 units/s per unit of overlap, at most `sep.max` 0.6 × top speed; shut trapdoor holes don't count.
- Rivers: `viaFord` (ai/crossing.ts) and the last stand's flow field (ai/flow.ts, `LastStandState.flow`) are gone; `groundMobility` too. `pathBlocked` lives in nav.ts.
- Moved to tuning.ts (were inline): `STEER` (pace and arrive gains, frame margin), `LAST_STAND.replan`/`release`/`coverRecheck`/`aroundHull`, `COVER.jitter`.
- Bot (12 seeds × 9 scenarios, 60 s each, demo bot): time mobile units spend stuck (< 3 units/s) 1.3–5.0% → 0.2–1.2%; unit overlaps down 2–6×; non-bomb-truck crushes 12 → 5. Kills and the convoy's fate unchanged. Sim cost ~+25% (~25 ms per 60 s battle).
- Tests: `tests/sim/nav.test.ts` (a wall's gap, a ford vs a hovercraft over the water, round a wood, an unreachable goal, round the hull, out of a zone, a charge ignoring both, separation).

`M3` · `dfa7791` · `playtest: pending` · SPEC §11.3 "Fire and smoke", §16 Q39

- **Gotcha:** heat only enters a field on a step (`add` writes to a pending buffer), so a patch is never drawn as a raw disc, and the texture only changes on a step.
- **Gotcha:** flames rise up the *screen* (the field knows nothing of the sim's axes); `FlameLayer.at` is the only place sim coordinates turn into field ones.
- **Gotcha:** `Effects` methods that take sim coordinates must call the layer before they convert `x, y` to view coordinates (`detonation`'s delayed blasts convert back).
- **Limits:** no wind (flames and smoke don't lean with a storm); the smoke the sim counts is per tile while the drawn smoke rolls up the screen about a tile past it; fire doesn't crackle; the title's attract mode shares all of it.

Channel inputs are forced to two channels (`channelCountMode: 'explicit'`) so every voice gets the same law; without it the inserts' splitters also see one channel when only mono notes are sounding.
- **Gotcha:** hard-left and hard-right desks plus the ensemble made the strings and choir *anti*-correlated (−0.12: they'd thin out in mono). `lean(0.5)` before the ensemble brings them to about 0.7.
- **Gotcha:** the convolver normalises its impulse by RMS, so the hall's loudness goes with the square root of the buffer's length, whatever its shape: lengthen `HALL_SECONDS` and the reverb gets louder.
- **Gotcha:** the inserts' LFOs never stop on their own; `MusicEngine.destroy()` stops them (`running`), or every battle would leave six behind.
